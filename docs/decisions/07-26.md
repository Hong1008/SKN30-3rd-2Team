# 2026-07-26: DB 스냅샷 호스팅 및 GCP Cloud Run 수동 배포 아키텍처 결정

## 1. 맥락 (Context)
WorkShield MCP 서버는 SQLite(`data/migration/*.sqlite3`) 및 Chroma Vector DB(`data/chroma/`) 스냅샷 데이터를 기반으로 무상태(Stateless)로 작동합니다.
클라우드 배포 시 인프라 비용 최소화, 이미지 및 데이터 트래킹의 명확성, 배포 안정성(롤백 및 재현성)을 보장하기 위한 아키텍처 결정을 기록합니다.

---

## 2. 결정 사항 (Decisions)

### A. DB 스냅샷 저장 및 이미지 빌드 방식
* **현상 유지**: 현재 DB 스냅샷 데이터 전체 용량이 소용량(SQLite ~0.88MB, Chroma DB ~9.7MB) 수준이므로, `.gitignore`에서 해당 경로 주석을 해제하여 Git 커밋 대상에 포함합니다.
* **Dockerfile**: Dockerfile의 `COPY data/migration/ ./data/migration/` 및 `COPY data/chroma/ ./data/chroma/` 레이어를 수정 없이 유지하여 빌드합니다.

### B. CI/CD 파이프라인 및 배포 불변성
* **이미지 저장소**: **GHCR (GitHub Container Registry)**를 사용하여 퍼블릭/프라이빗 무제한 무료 혜택을 활용합니다.
* **배포 타겟**: **GCP Cloud Run** (`asia-northeast3` 서울 리전, `min-instances=0` 스케일 투 제로 설정으로 서버리스 $0 제어).
* **트리거 규칙**: 브랜치 푸시 시 자동 배포를 금지하고, 개발자의 명시적 **수동 트리거(`workflow_dispatch`)**로만 배포를 실행합니다.
* **배포 불변성 (Immutability)**: 배포 시 가변 태그인 `:latest` 대신 커밋 해시 기반의 **불변 태그 (`:${{ github.sha }}`)**를 Cloud Run의 배포 타겟으로 지정합니다. (롤백 및 재현성 보장)

### C. 환경변수 관리 CLI 레시피
* 로컬 `.env` 파일의 시크릿 키는 Git에 포함시키지 않으며, GCP 콘솔 또는 `just set-cloudrun-env` CLI 레시피를 이용해 `gcloud run services update`로 주입합니다.

---

## 3. 미래 대용량화 시 전환 아키텍처 (Roadmap)

DB 파생물(`data/chroma/`, `data/migration/`) 데이터 용량이 급증하여 수백 MiB 이상이 될 경우, 이미지 크기 감소 및 CI/CD 빌드 시간 단축을 위해 아래와 같이 **GitHub Release 전환 아키텍처**를 적용합니다.

```
[전환 시 런타임 흐름]
Cloud Run 인스턴스 시작
 └─► curl로 DATA_SNAPSHOT_URL 다운로드 (/tmp/snapshot.tar.gz)
 └─► sha256sum 무결성 검증 (DATA_SNAPSHOT_SHA256)
 └─► 검증 성공 시 /app/data 로 원자적(Atomic) 이동 후 서버 시작
```

1. **GitHub Release 파일 호스팅**: `data_snapshot.tar.gz`를 GitHub Release Asset에 호스팅 ($0 무료 & 고속 CDN).
2. **Dockerfile 런타임 지원**: Dockerfile에 `curl` 및 `ca-certificates` 설치 유지.
3. **무결성 검증 및 원자적 이동**: `/tmp`에 다운로드받은 바이너리를 SHA-256 검증 완료 후에만 `/app/data`로 이동하여 훼손된 데이터의 런타임 로딩을 원천 차단.
